# Установка и эксплуатация (руководство администратора)

## 1. Требования

Сервер Linux (x86-64 или ARM64) с systemd. Дополнительное ПО не требуется: ни СУБД, ни веб-сервер, ни интерпретаторы, ни контейнеры.

## 2. Установка

```sh
sudo sh deploy/install.sh lms.example.ru "Название организации" "Название портала"
```

Сценарий проверяет контрольную сумму, создаёт системного пользователя `kafedra`, каталоги, самоподписанный сертификат, конфигурацию, инициализирует хранилище и запускает службу. В конце выводится **временный пароль администратора** (один раз).

| Что | Где |
|---|---|
| Исполняемый файл | `/opt/kafedra/kafedra` |
| Конфигурация | `/opt/kafedra/config.json` |
| Сертификат и ключ TLS | `/opt/kafedra/cert.pem`, `key.pem` |
| Данные | `/opt/kafedra/data` (`db/`, `files/`, `audit/`, `backup/`, `master.key`) |
| Журнал работы | `/var/log/kafedra/kafedra.log` |

Всё, что нужно программе, лежит в одном каталоге `/opt/kafedra`; каталоги `/etc` и `/var/lib` не используются. Вне этого каталога находятся только журнал (`/var/log/kafedra`) и файл службы systemd (`/etc/systemd/system/kafedra.service` — другого места для него в системе нет).

Права: каталог и исполняемый файл принадлежат root, поэтому служба не может подменить собственную программу. Служебной учётной записи `kafedra` принадлежат каталог данных, `config.json` и журнал.

Эти пути — значения по умолчанию, зашитые в программу: команды без параметра `-config` читают `/opt/kafedra/config.json`. Для другого расположения укажите `-config путь` и задайте `data_dir` и `log_file` в файле.

Ручная установка: скопируйте файл, выполните `kafedra init -config ...`, затем `kafedra serve -config ...`.

### После установки
1. Войдите как `admin`, смените пароль. Двухфакторная аутентификация подключается по желанию в «Профиле»; сделать её обязательной можно параметром `mfa_required_for`.
2. Замените самоподписанный сертификат на выданный удостоверяющим центром, перезапустите службу.
3. **Скопируйте `/opt/kafedra/data/master.key` в защищённое место** (сейф, отдельный носитель). Без него пароли из резервной копии проверить невозможно.
4. Проверьте `timezone` в `/opt/kafedra/config.json`.
5. Создайте группы, пользователей (вручную или импортом CSV), курсы.

## 3. Конфигурация (`config.json`)

Все основные настройки хранятся в одном файле с отступами и понятными именами параметров. Отсутствующие параметры получают значения по умолчанию; неизвестные параметры считаются ошибкой (защита от опечаток). Относительные пути отсчитываются от каталога, где лежит файл.

| Параметр | Назначение |
|---|---|
| `listen` | адрес и порт, например `:443` или `127.0.0.1:8080` |
| `data_dir` | каталог данных; по умолчанию `/opt/kafedra/data` |
| `log_file` | файл журнала работы службы, по умолчанию `/var/log/kafedra/kafedra.log`; сюда же дублируются события безопасности (строки `AUDIT`). Значение `"-"` — только стандартный вывод (journald) |
| `audit_dir` | каталог журнала событий безопасности; пусто — `<data_dir>/audit` |
| `tls_cert`, `tls_key` | сертификат и ключ; если пусто — HTTP (только за обратным прокси с TLS или для пробы) |
| `trusted_proxy` | IP обратного прокси; только от него принимаются `X-Forwarded-For` и `X-Forwarded-Proto` |
| `timezone` | часовой пояс, например `Europe/Moscow`, `Asia/Yekaterinburg` |
| `portal_name` | первая строка заголовка — название портала |
| `org_name` | вторая строка заголовка — название организации |
| `logo_file` | файл логотипа в заголовке и на странице входа: PNG, SVG, JPEG или WebP, до 2 МБ; пусто — встроенный значок |
| `backup_hour`, `backup_keep` | час ежесуточной копии (−1 — выключить) и число хранимых копий |
| `settings` | парольная политика, блокировки, сеансы, второй фактор, шкала оценок, файлы — см. ниже |

Раздел `settings` можно менять двумя способами: в веб-интерфейсе («Настройки» — изменения сразу записываются в `config.json`) или в файле (после правки — `systemctl restart kafedra`). Остальные параметры меняются только в файле. Если файл недоступен службе для записи, интерфейс сообщит об этом, а изменения будут действовать до перезапуска.

Основные параметры `settings`: `password_min_length`, `password_need_*`, `password_history`, `password_max_age_days`, `lock_after_failed_attempts`, `lock_minutes`, `session_idle_minutes`, `session_max_hours`, `max_sessions_per_user`, `mfa_required_for` (`none` — по желанию, `admin`, `staff`, `all`), `totp_time_window_steps`, `grade5_from_percent` / `grade4_…` / `grade3_…`, `rating_show_names`, `teachers_create_courses`, `allowed_extensions`, `max_upload_mb`, `login_banner`.

Название продукта и правообладатель в нижней строке интерфейса не настраиваются.

### Файлы данных и их читаемость

| Файл | Формат |
|---|---|
| `config.json` | JSON с отступами |
| `db/snapshot.json` | JSON с отступами: все данные, сгруппированные по коллекциям (`users`, `courses`, `items` …). Обновляется раз в час и при остановке службы |
| `db/journal.jsonl` | операции, выполненные после последнего снимка: одна операция — одна строка JSON с контрольной суммой. Построчная запись нужна для восстановления после сбоя питания; при остановке службы журнал пуст |
| `audit/audit-ГГГГ-ММ.log` | журнал событий безопасности: одна запись — одна строка JSON (так устроена защита цепочкой хешей и построчная передача в SIEM) |

Править `snapshot.json` вручную можно только при остановленной службе.

## 4. Команды

Выполняйте команды от имени служебной учётной записи, чтобы не нарушить права на файлы данных: `runuser -u kafedra -- /opt/kafedra/kafedra <команда>`.

```
kafedra init [-config ...] [-admin логин] [-listen ...] [-portal ...] [-org ...] [-data ...] [-log ...] [-demo]
kafedra serve [-config ...]
kafedra backup  [-config ...] [-out файл.zip] [-with-key]    # служба остановлена
kafedra restore [-config ...] -in файл.zip                   # служба остановлена
kafedra passwd  [-config ...] -login имя                     # служба остановлена; сбрасывает пароль, блокировку и 2ФА
kafedra audit-verify [-config ...]
kafedra gencert -host имя -out каталог
```

Хранилище защищено блокировкой: пока служба работает, команды `backup`, `restore`, `passwd` откажутся выполняться.

## 5. Резервное копирование

- **Автоматически** каждую ночь в `data/backup/kafedra-ГГГГММДД.zip`, хранится `backup_keep` копий.
- **Немедленно на работающей службе:** `systemctl kill -s USR1 kafedra` либо «Система → Скачать резервную копию».
- **Полная копия с ключом:** остановить службу, `kafedra backup -with-key -out /путь/копия.zip`.

Копии содержат базу, файлы и журнал событий. Автоматические копии и копии из браузера **не содержат мастер-ключ**. Выносите копии на другой носитель: каталог `backup` на том же диске не защищает от отказа диска.

Восстановление: `systemctl stop kafedra` → `kafedra restore -in копия.zip` → при необходимости вернуть `master.key` → `systemctl start kafedra`. Периодически проверяйте восстановление на тестовом сервере.

## 6. Обновление

Остановить службу, сделать копию, заменить `/opt/kafedra/kafedra`, сверить SHA-256, запустить. Формат хранилища совместим вперёд: неизвестные поля и коллекции сохраняются.

## 7. Контроль и диагностика

- Журнал службы: файл из `log_file` и `journalctl -u kafedra`; строки с префиксом `AUDIT` — события безопасности в JSON (можно передавать в SIEM). Ротацию файла настройте средствами ОС (logrotate, режим `copytruncate`).
- «Журнал событий» — просмотр, фильтр, проверка целостности; то же из консоли: `kafedra audit-verify`.
- «Система» — версия, контрольная сумма исполняемого файла, сеансы, объём данных.

## 8. Работа за обратным прокси

Если TLS завершается на прокси (в том числе на сертифицированном средстве с ГОСТ-TLS): `listen: "127.0.0.1:8080"`, пустые `tls_cert`/`tls_key`, `trusted_proxy: "127.0.0.1"`. Прокси обязан передавать `X-Forwarded-For`, `X-Forwarded-Proto: https` и исходный `Host`; лимит размера тела запроса на прокси должен быть не меньше лимита загрузки файлов.

## 9. Работа в закрытом контуре (без интернета)

Продукт не обращается во внешнюю сеть: нет загрузки шрифтов, сценариев, обновлений, телеметрии; база часовых поясов встроена в исполняемый файл. Установка и сборка также не требуют сети.

**Двухфакторный вход работает без интернета.** Используется стандарт TOTP (RFC 6238): сервер и приложение-аутентификатор независимо вычисляют код из общего секрета и текущего времени, друг с другом и с внешними сервисами не связываются. Телефону интернет тоже не нужен. Условия:

1. **Точное время на сервере.** Без доступа к публичным NTP-серверам настройте синхронизацию с внутренним источником времени контура. При расхождении часов сервера и телефона больше допуска коды не подойдут.
2. Допуск задаётся параметром `totp_time_window_steps` (по умолчанию 1 — это ±30 секунд; 2 — ±60 секунд). Увеличивайте, только если часы в контуре идут неточно.
3. Ключ вводится в приложение вручную (QR-код не формируется), поэтому подойдёт любое приложение-аутентификатор, в том числе установленное заранее или из внутреннего хранилища приложений.
4. Если в контур нельзя проносить телефоны, второй фактор остаётся выключенным (значение по умолчанию) либо используется аппаратный генератор TOTP-кодов с возможностью записи ключа.

Самоподписанный сертификат создаётся командой `gencert` без сети; для отсутствия предупреждений браузера выпустите сертификат во внутреннем удостоверяющем центре.

## 10. Типовые неполадки

| Признак | Действие |
|---|---|
| «хранилище уже используется другим процессом» | остановите службу перед командами `backup`/`restore`/`passwd` |
| «файл ключа доступен посторонним» | `chmod 600 master.key`, владелец — `kafedra` |
| «файл журнала недоступен» при запуске | создайте `/var/log/kafedra` с правами для учётной записи службы либо измените `log_file` |
| Коды второго фактора не подходят | проверьте время на сервере и телефоне; при необходимости увеличьте `totp_time_window_steps` |
| Администратор потерял устройство 2ФА | `systemctl stop kafedra; runuser -u kafedra -- /opt/kafedra/kafedra passwd -login admin; systemctl start kafedra` |
| После входа снова страница входа (HTTP без TLS за прокси) | проверьте `trusted_proxy` и заголовок `X-Forwarded-Proto` |
| «Запрос отклонён» при отправке форм за прокси | прокси подменяет `Host`; настройте передачу исходного заголовка |
