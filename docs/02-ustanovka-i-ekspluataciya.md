# Установка и эксплуатация (руководство администратора)

## 1. Требования

Сервер Linux (x86-64 или ARM64) с systemd. Дополнительное ПО не требуется: ни СУБД, ни веб-сервер, ни интерпретаторы, ни контейнеры.

## 2. Установка

```sh
sudo sh deploy/install.sh lms.example.ru "Название организации" "Название портала"
```

Сценарий проверяет контрольную сумму, создаёт системного пользователя `kafedra`, каталоги, самоподписанный сертификат, конфигурацию, инициализирует хранилище и запускает службу. В конце выводится **временный пароль администратора** (один раз).

| Что | Где |
|---|---|
| Исполняемый файл | `/opt/kafedra/kafedra` |
| Конфигурация | `/opt/kafedra/config.json` |
| Сертификат и ключ TLS | `/opt/kafedra/cert.pem`, `key.pem` |
| Данные | `/opt/kafedra/data` (`db/`, `files/`, `audit/`, `backup/`, `master.key`) |
| Журнал работы | `/var/log/kafedra/kafedra.log` |

Всё, что нужно программе, лежит в одном каталоге `/opt/kafedra`; каталоги `/etc` и `/var/lib` не используются. Вне этого каталога находятся только журнал (`/var/log/kafedra`) и файл службы systemd (`/etc/systemd/system/kafedra.service` — другого места для него в системе нет).

Права: каталог и исполняемый файл принадлежат root, поэтому служба не может подменить собственную программу. Служебной учётной записи `kafedra` принадлежат каталог данных, `config.json` и журнал.

Эти пути — значения по умолчанию, зашитые в программу: команды без параметра `-config` читают `/opt/kafedra/config.json`. Для другого расположения укажите `-config путь` и задайте `data_dir` и `log_file` в файле.

Ручная установка: скопируйте файл, выполните `kafedra init -config ...`, затем `kafedra serve -config ...`.

### После установки
1. Войдите как `admin`, смените пароль. Двухфакторная аутентификация подключается по желанию в «Профиле»; сделать её обязательной можно параметром `mfa_required_for`.
2. Замените самоподписанный сертификат на выданный удостоверяющим центром, перезапустите службу.
3. **Скопируйте `/opt/kafedra/data/master.key` в защищённое место** (сейф, отдельный носитель). Без него пароли из резервной копии проверить невозможно.
4. Проверьте `timezone` в `/opt/kafedra/config.json`.
5. Создайте группы, пользователей (вручную или импортом CSV), курсы.

## 3. Конфигурация (`config.json`)

Все основные настройки хранятся в одном файле с отступами и понятными именами параметров. Отсутствующие параметры получают значения по умолчанию; неизвестные параметры считаются ошибкой (защита от опечаток). Относительные пути отсчитываются от каталога, где лежит файл.

| Параметр | Назначение |
|---|---|
| `listen` | адрес и порт, например `:443` или `127.0.0.1:8080` |
| `data_dir` | каталог данных; по умолчанию `/opt/kafedra/data` |
| `log_file` | файл журнала работы службы, по умолчанию `/var/log/kafedra/kafedra.log`; сюда же дублируются события безопасности (строки `AUDIT`). Значение `"-"` — только стандартный вывод (journald) |
| `audit_dir` | каталог журнала событий безопасности; пусто — `<data_dir>/audit` |
| `tls_cert`, `tls_key` | сертификат и ключ; оба пусто — работа без сертификатов по HTTP за общим веб-сервером (раздел 8) |
| `external_url` | адрес портала для пользователей при работе за веб-сервером, например `https://lms.example.ru` |
| `trusted_proxy` | IP веб-сервера (несколько — через запятую); только от него принимаются `X-Real-IP`, `X-Forwarded-For`, `X-Forwarded-Proto`, `X-Forwarded-Host` |
| `timezone` | часовой пояс, например `Europe/Moscow`, `Asia/Yekaterinburg` |
| `portal_name` | первая строка заголовка — название портала |
| `org_name` | вторая строка заголовка — название организации |
| `logo_file` | файл логотипа в заголовке и на странице входа: PNG, SVG, JPEG или WebP, до 2 МБ; пусто — встроенный значок |
| `certificate_icon` | значок на сертификате: PNG или JPEG. Пусто — логотип портала (`logo_file`, если он PNG/JPEG), иначе встроенный значок |
| `certificate_font` | файл шрифта TrueType (.ttf) с кириллицей для сертификатов. Пусто — поиск в системе (PT Sans, Liberation Sans, DejaVu Sans) |
| `personal_data_operator_address` | адрес оператора персональных данных — подставляется в бланк согласия |
| `smtp_allow_plain` | `true` — разрешить отправку без шифрования на внутренний сервер без STARTTLS; только без `smtp_user` |
| `smtp_addr`, `smtp_from`, `smtp_user`, `smtp_password` | почтовый сервер организации (`узел:порт`) и адрес отправителя для рассылки сертификатов; пусто — письма не отправляются |
| `backup_hour`, `backup_keep` | час ежесуточной копии (−1 — выключить) и число хранимых копий |
| `settings` | парольная политика, блокировки, сеансы, второй фактор, шкала оценок, файлы — см. ниже |

Раздел `settings` можно менять двумя способами: в веб-интерфейсе («Настройки» — изменения сразу записываются в `config.json`) или в файле (после правки — `systemctl restart kafedra`). Остальные параметры меняются только в файле. Если файл недоступен службе для записи, интерфейс сообщит об этом, а изменения будут действовать до перезапуска.

Основные параметры `settings`: `password_min_length`, `password_need_*`, `password_history`, `password_max_age_days`, `login_failures_per_address`, `lock_after_failed_attempts`, `lock_minutes`, `session_idle_minutes`, `session_max_hours`, `max_sessions_per_user`, `mfa_required_for` (`none` — по желанию, `admin`, `staff`, `all`), `totp_time_window_steps`, `grade5_from_percent` / `grade4_…` / `grade3_…`, `rating_show_names`, `teachers_create_courses`, `teachers_import_students`, `questionnaire_required`, `questionnaire_email`, `certificate_requires_application`, `chat_max_file_mb`, `allowed_extensions`, `max_upload_mb`, `login_banner`.

Название продукта и правообладатель в нижней строке интерфейса не настраиваются.

### Файлы данных и их читаемость

| Файл | Формат |
|---|---|
| `config.json` | JSON с отступами |
| `db/snapshot.json` | JSON с отступами: все данные, сгруппированные по коллекциям (`users`, `courses`, `items` …). Обновляется раз в час и при остановке службы |
| `db/journal.jsonl` | операции, выполненные после последнего снимка: одна операция — одна строка JSON с контрольной суммой. Построчная запись нужна для восстановления после сбоя питания; при остановке службы журнал пуст |
| `audit/audit-ГГГГ-ММ.log` | журнал событий безопасности: одна запись — одна строка JSON (так устроена защита цепочкой хешей и построчная передача в SIEM) |

Править `snapshot.json` вручную можно только при остановленной службе.

### Шрифт для сертификатов

PDF с русским текстом требует внедрённого шрифта. Программа шрифтов не содержит и берёт шрифт, установленный в операционной системе. В Astra Linux, РЕД ОС и Альт шрифты PT, Liberation или DejaVu обычно установлены; если нет — установите пакет шрифтов (например, `fonts-liberation`, `liberation-fonts`, `fonts-ttf-liberation`, `fonts-dejavu`) либо укажите файл в `certificate_font`. Если шрифт не найден, учащийся увидит сообщение, а в журнале событий появится запись с причиной. Поддерживаются файлы .ttf; .otf и .ttc не поддерживаются.

### Анкета, заявление, почта

| Параметр | Поведение |
|---|---|
| `questionnaire_required` | учащийся не допускается к материалам, пока администратор не откроет доступ после проверки анкеты |
| `questionnaire_email` | адрес, на который учащиеся отправляют анкету; пусто — показывается адрес преподавателя курса |
| `certificate_requires_application` | сертификат выдаётся после загрузки скана подписанного заявления и подтверждения сверки |

В новой установке оба режима **включены**. При обновлении с прежней версии (в `config.json` этих параметров нет) они остаются **выключенными**, чтобы не закрыть доступ работающим учащимся; включите их в «Настройках». При включении анкеты на действующем портале откройте доступ уже обучающимся: курс → «Участники» → «Открыть доступ всем учащимся курса» (кнопка видна только администратору).

Почта. Укажите `smtp_addr` (например, `mail.example.local:587` или `mail.example.local:465`) и `smtp_from`. Для порта 465 используется TLS сразу после подключения, для остальных портов требуется STARTTLS. Для почтового релея на том же сервере допускается передача через loopback без TLS. Если внутренний почтовый сервер закрытого контура не поддерживает шифрование, задайте `"smtp_allow_plain": true`: письма пойдут открытым текстом, поэтому параметр несовместим с `smtp_user` — пароль без шифрования не передаётся. Сертификат TLS почтового сервера проверяется по системному хранилищу: корневой сертификат внутреннего удостоверяющего центра должен быть установлен в ОС, а имя узла в `smtp_addr` — совпадать с именем в сертификате. Ограничьте доступ к `config.json`, в нём хранятся реквизиты SMTP. Задание отправки сохраняется вместе с сертификатом и подхватывается после перезапуска службы. После сбоя выполняется до пяти повторов, результаты фиксируются в аудите; после окончательной неудачи письмо ставится в очередь заново кнопкой «Отправить» во вкладке «Участники». Бланки из почтового ящика проверяет администратор портала.

### Вход с одного адреса и производительность

- **Ограничение по адресу.** Считаются только неудачные попытки входа: `login_failures_per_address` (по умолчанию 100 за 10 минут с одного адреса, меняется в «Настройках»). Успешные входы лимит не расходуют, поэтому учебный класс за NAT или пользователи за общим веб-сервером входят без ограничений. Учётная запись дополнительно блокируется после `lock_after_failed_attempts` неверных паролей.
- **Проверка пароля намеренно медленная** (PBKDF2, 600 000 итераций, около 0,1–0,3 с на одно ядро). Одновременно вычисляется не больше «число ядер − 1» хешей, остальные ждут в очереди; сохранение ответов и сдача тестов при этом не задерживаются. Смена пароля требует двух-трёх вычислений.
- **Ориентир по замеру** (2 ядра, 300 учащихся одновременно входят, меняют временный пароль и проходят тест): ошибок нет, память службы около 35 МБ, сохранение ответа — до 0,1 с, начало и сдача теста — до 0,05 с. Вход последнего в очереди — около 35 с, смена пароля — около 75 с. Для потоков больше 100 человек, входящих одновременно, выделяйте 4 ядра и более, а временные пароли меняйте заранее, не в день экзамена. Время ожидания ответа на внешнем веб-сервере (`proxy_read_timeout` и аналоги) задайте не меньше 120 с.

## 4. Команды

Выполняйте команды от имени служебной учётной записи, чтобы не нарушить права на файлы данных: `runuser -u kafedra -- /opt/kafedra/kafedra <команда>`.

```
kafedra init [-config ...] [-admin логин] [-listen ...] [-portal ...] [-org ...] [-data ...] [-log ...] [-demo]
kafedra serve [-config ...]
kafedra backup  [-config ...] [-out файл.zip] [-with-key]    # служба остановлена
kafedra restore [-config ...] -in файл.zip [-allow-incomplete]   # служба остановлена
kafedra passwd  [-config ...] -login имя                     # служба остановлена; сбрасывает пароль, блокировку и 2ФА
kafedra audit-verify [-config ...] [-accept-archived-prefix]
kafedra gencert -host имя -out каталог
```

Хранилище защищено блокировкой: пока служба работает, команды `backup`, `restore`, `passwd` откажутся выполняться.

## 5. Резервное копирование

- **Автоматически** каждую ночь в `data/backup/kafedra-ГГГГММДД.zip`, хранится `backup_keep` копий.
- **Немедленно на работающей службе:** `systemctl kill -s USR1 kafedra` либо «Система → Скачать резервную копию».
- **Полная копия с ключом:** остановить службу, `kafedra backup -with-key -out /путь/копия.zip`.

Копии содержат базу, вложения и журнал событий. Автоматические копии и копии из браузера **не содержат мастер-ключ**. Выносите копии на другой носитель.

Как это работает:
- Запись в базу приостанавливается только на время снятия снимка базы (доли секунды); вложения копируются после этого, работа пользователей не останавливается.
- Каждое вложение сверяется по размеру и контрольной сумме. Если файл пропал или повреждён, **копия всё равно создаётся**, а идентификаторы таких файлов записываются в `manifest.json` (поле `damaged_files`), в журнал службы и в журнал событий как отказ. Проверяйте журнал событий с отбором «Только отказы и ошибки».
- Неполная автоматическая копия не вытесняет предыдущие при ротации. Восстановить неполную копию можно только с ключом `-allow-incomplete` — повреждённые вложения при этом удаляются из базы.
- Файл, удалённый пользователем во время копирования, всё равно попадает в текущую копию: удаление с диска откладывается до её завершения.
- Через браузер копия сначала формируется во временном файле в `data/backup` — нужно свободное место в размере копии.

Восстановление: `systemctl stop kafedra` → `kafedra restore -in копия.zip` → `systemctl start kafedra`. Архив сначала распаковывается и проверяется во временном каталоге (нужно свободное место в размере данных), затем данные заменяются с возможностью отката; сеансы пользователей сбрасываются. Если в архиве нет мастер-ключа, он должен уже лежать в каталоге данных и соответствовать копии. Журнал событий заменяется журналом из копии. Если восстановление прервано, служба не запустится с сообщением «обнаружено незавершённое восстановление» — повторите команду `restore`.

### Журнал событий: запуск, архив, восстановление

При запуске служба проверяет целостность журнала событий и не запускается, если цепочка нарушена.

| Ситуация | Что происходит |
|---|---|
| Сбой питания во время записи: последняя строка оборвана | оборванная строка отбрасывается автоматически, в журнал добавляется запись о восстановлении |
| Файлы за старые месяцы перенесены в архив | остановите службу, перенесите **только самые ранние** файлы `audit-ГГГГ-ММ.log` подряд, без пропусков, затем подтвердите перенос: `kafedra audit-verify -accept-archived-prefix`. Подтверждение требует исходной контрольной точки. Если она потеряна, сначала восстановите её или полный журнал из проверенной копии. |
| Удалён файл из середины или последний, изменена запись | служба не запустится: «нарушена целостность журнала» либо «журнал усечён» |

Если служба не запускается из-за журнала: 1) сохраните каталог журнала как есть — это материал для разбора; 2) верните файлы из резервной копии либо, по решению ответственного за безопасность, перенесите повреждённые файлы **и** `audit-head.json` в другое место — служба начнёт новый журнал; 3) зафиксируйте случай в документах организации.

Файл `audit-head.json` — контрольная точка (номер и хеш последней записи). Она позволяет заметить случайное усечение журнала, но не защищает от того, кто имеет права на запись в каталог журнала: для этого нужна передача событий во внешнюю систему.

## 6. Обновление

### Переход с версии 1.0 (данные в `/var/lib/kafedra`, конфигурация в `/etc/kafedra`)

```sh
systemctl stop kafedra
systemctl unmask kafedra 2>/dev/null; rm -f /etc/systemd/system/kafedra.service
install -d -m 0755 /opt/kafedra
mv /var/lib/kafedra /opt/kafedra/data
mv /etc/kafedra/config.json /opt/kafedra/config.json
# в config.json: "data_dir": "/opt/kafedra/data"; при работе без сертификатов tls_cert и tls_key — пустые
install -d -m 0750 -o kafedra -g kafedra /var/log/kafedra
install -m 0755 dist/kafedra-linux-amd64 /opt/kafedra/kafedra
chown -R kafedra:kafedra /opt/kafedra/data /opt/kafedra/config.json
chmod 0600 /opt/kafedra/config.json
install -m 0644 deploy/kafedra.service /etc/systemd/system/kafedra.service
systemctl daemon-reload && systemctl enable --now kafedra
```

Старый файл конфигурации подходит: недостающие параметры получают значения по умолчанию, устаревший `system_name` игнорируется. Настройки безопасности, заданные в интерфейсе версии 1.0, не переносятся — задайте их заново (раздел `settings`).

### Переход на 1.4.4

Замените исполняемый файл и перезапустите службу. Формат данных не менялся. Если программа работает за внешним веб-сервером, проверьте, что задан `trusted_proxy` и веб-сервер передаёт `X-Real-IP`: иначе все пользователи видны с одного адреса (служба предупреждает об этом при запуске).

### Переход на 1.4.2

Замените исполняемый файл и перезапустите службу. Формат данных не менялся. Если почтовый сервер не предлагает STARTTLS и версия 1.4.1 из-за этого не отправляла письма, задайте `smtp_allow_plain` и повторите отправку кнопкой «Отправить».

### Переход на 1.4.1

Замените исполняемый файл на собранный для вашей архитектуры и перезапустите службу. Если обязательное заявление включено, ранее загруженные сканы без решения появятся у преподавателя как ожидающие сверки. Ранее выданные сертификаты доступны для скачивания, задания рассылки для них автоматически не создаются. Если настроен удалённый SMTP, проверьте поддержку TLS. При переносе ранних месяцев аудита сохраните контрольную точку и исходный архив.

### Переход на 1.4.0 с версий 1.3.x

Замените исполняемый файл, перезапустите. Формат данных совместим. Обсуждения курсов становятся чатами курсов в разделе «Общение». Анкета и обязательное заявление после обновления выключены (см. раздел 3).

### Переход на 1.3.0 с версий 1.2.x

Замените исполняемый файл и файл службы, перезапустите. Формат данных совместим. После обновления: пользователи со вторым фактором вводят код заново; в `config.json` появятся новые параметры при первом сохранении настроек из интерфейса.

### Обычное обновление

Остановить службу, сделать копию, заменить `/opt/kafedra/kafedra`, сверить SHA-256, запустить. Формат хранилища совместим вперёд: неизвестные поля и коллекции сохраняются.

## 7. Контроль и диагностика

- Журнал службы: файл из `log_file` и `journalctl -u kafedra`; строки с префиксом `AUDIT` — события безопасности в JSON (можно передавать в SIEM). Ротацию файла настройте средствами ОС (logrotate, режим `copytruncate`).
- «Журнал событий» — просмотр, фильтр, проверка целостности; то же из консоли: `kafedra audit-verify`.
- «Система» — версия, контрольная сумма исполняемого файла, сеансы, объём данных.

## 8. Работа без сертификатов, за общим веб-сервером

Штатный режим для контура, где HTTPS обеспечивает общий веб-сервер, а трафик перенаправляется на порт внутреннего сервера. Сертификаты программе не нужны: оставьте `tls_cert` и `tls_key` пустыми — она принимает обычный HTTP на своём порту.

```json
{
  "listen": ":4444",
  "tls_cert": "",
  "tls_key": "",
  "external_url": "https://lms.example.ru",
  "trusted_proxy": "10.0.0.5"
}
```

| Параметр | Зачем |
|---|---|
| `external_url` | адрес, который пользователи набирают в браузере. По нему программа понимает, что пользователь работает по HTTPS (защищённая сеансовая кука, HSTS), и принимает формы, даже если веб-сервер подменяет заголовок `Host` |
| `trusted_proxy` | IP-адрес веб-сервера, с которого приходят запросы (несколько — через запятую). Только от него принимаются `X-Real-IP` / `X-Forwarded-For`, чтобы в журнале событий и при блокировках учитывался адрес пользователя, а не веб-сервера |

Оба параметра необязательны — без них программа тоже запустится и будет работать, но в журнале событий будет адрес веб-сервера, а ограничение числа попыток входа станет общим для всех пользователей.

Установка сразу в этом режиме:

```sh
sudo NO_TLS=1 LISTEN=:4444 EXTERNAL_URL=https://lms.example.ru TRUSTED_PROXY=10.0.0.5 \
  sh deploy/install.sh lms.example.ru "Организация" "Портал"
```

Пример для nginx на общем веб-сервере:

```nginx
location / {
    proxy_pass http://10.0.0.20:4444;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto https;
    client_max_body_size 210m;       # не меньше max_upload_mb
    proxy_request_buffering off;     # загрузка больших файлов
    proxy_read_timeout 300s;
}
```

Ограничения: портал должен публиковаться в корне отдельного имени (`https://lms.example.ru/`), публикация в подкаталоге (`https://example.ru/lms/`) не поддерживается. Закройте порт программы межсетевым экраном для всех, кроме веб-сервера: при заданном `external_url` с `https` вход напрямую по HTTP намеренно не работает (кука сеанса передаётся только по HTTPS).

## 9. Работа в закрытом контуре (без интернета)

Продукт не обращается во внешнюю сеть: нет загрузки шрифтов, сценариев, обновлений, телеметрии; база часовых поясов встроена в исполняемый файл. Установка и сборка также не требуют сети.

**Двухфакторный вход работает без интернета.** Используется стандарт TOTP (RFC 6238): сервер и приложение-аутентификатор независимо вычисляют код из общего секрета и текущего времени, друг с другом и с внешними сервисами не связываются. Телефону интернет тоже не нужен. Условия:

1. **Точное время на сервере.** Без доступа к публичным NTP-серверам настройте синхронизацию с внутренним источником времени контура. При расхождении часов сервера и телефона больше допуска коды не подойдут.
2. Допуск задаётся параметром `totp_time_window_steps` (по умолчанию 1 — это ±30 секунд; 2 — ±60 секунд). Увеличивайте, только если часы в контуре идут неточно.
3. Ключ вводится в приложение вручную (QR-код не формируется), поэтому подойдёт любое приложение-аутентификатор, в том числе установленное заранее или из внутреннего хранилища приложений.
4. Если в контур нельзя проносить телефоны, второй фактор остаётся выключенным (значение по умолчанию) либо используется аппаратный генератор TOTP-кодов с возможностью записи ключа.

Самоподписанный сертификат создаётся командой `gencert` без сети; для отсутствия предупреждений браузера выпустите сертификат во внутреннем удостоверяющем центре.

## 10. Типовые неполадки

| Признак | Действие |
|---|---|
| `Unit kafedra.service is masked` | файл службы пуст или служба замаскирована: `systemctl unmask kafedra; rm -f /etc/systemd/system/kafedra.service; install -m 0644 deploy/kafedra.service /etc/systemd/system/; systemctl daemon-reload; systemctl start kafedra` |
| «хранилище уже используется другим процессом» | остановите службу перед командами `backup`/`restore`/`passwd` |
| «файл ключа доступен посторонним» | `chmod 600 master.key`, владелец — `kafedra` |
| «файл журнала недоступен» при запуске | создайте `/var/log/kafedra` с правами для учётной записи службы либо измените `log_file` |
| Коды второго фактора не подходят | проверьте время на сервере и телефоне; при необходимости увеличьте `totp_time_window_steps` |
| Администратор потерял устройство 2ФА | `systemctl stop kafedra; runuser -u kafedra -- /opt/kafedra/kafedra passwd -login admin; systemctl start kafedra` |
| После входа снова страница входа | задан `external_url` с `https`, а портал открыт напрямую по HTTP — открывайте через веб-сервер либо уберите `external_url` |
| «Запрос отклонён» при отправке форм за веб-сервером | укажите `external_url` — адрес портала в браузере |
