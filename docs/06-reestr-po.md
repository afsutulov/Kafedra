# Реестр российского ПО: требования и готовность

Основание — ст. 12.1 Федерального закона № 149-ФЗ и Правила, утверждённые ПП РФ № 1236 (в 2025–2026 гг. существенно обновлены). Этот документ — рабочая памятка, а не юридическое заключение: перед подачей сверьтесь с действующей редакцией Правил и методическими материалами на reestr.digital.gov.ru либо привлеките юриста.

## 1. Что сделано в самом продукте

| Требование | Состояние |
|---|---|
| Отсутствие критической зависимости от иностранных компонентов | сторонних библиотек, фреймворков, СУБД, шрифтов и внешних сервисов нет |
| Нет принудительных обновлений и управления из-за рубежа | продукт не обращается в сеть: нет телеметрии, проверки обновлений, CDN, внешних счётчиков |
| Работа на российских ОС | статический исполняемый файл Linux x86-64/ARM64 без зависимостей от пакетов ОС. **Совместимость нужно подтвердить фактическим запуском** минимум на двух ОС из реестра (например, Astra Linux и РЕД ОС или Альт) и оформить протоколами: для прикладного ПО требование совместимости с двумя доверенными ОС вводится поэтапно, сроки зависят от класса |
| Свободная реализация на территории РФ, поддержка из РФ | обеспечивает правообладатель |
| Комплект документации | подготовлен (раздел 3) |
| Воспроизводимая сборка на инфраструктуре правообладателя | `build.sh`, сеть не нужна |

## 2. Перечень заимствованных компонентов

| Компонент | Роль | Лицензия | Правообладатель |
|---|---|---|---|
| Стандартная библиотека и среда исполнения Go | компонуется в исполняемый файл | BSD-3-Clause (разрешает коммерческое использование без ограничений по территории) | The Go Authors |
| База часовых поясов IANA (пакет `time/tzdata` из состава Go) | встроена в исполняемый файл | общественное достояние | — |
| Компилятор Go | средство разработки, в продукт не входит | BSD-3-Clause | The Go Authors |

Иных заимствований нет: хранилище, обработка разметки, импорт DOCX, веб-интерфейс, стили и значок написаны для этого проекта. Проверка: `go.mod` не содержит ни одной строки `require`; каталога `vendor` нет.

Честная оговорка: требование «без кода с открытыми исходными текстами» выполнено на уровне библиотек и прикладного кода, но язык Go и его стандартная библиотека сами являются открытым ПО зарубежного происхождения. Это общая ситуация для любого языка программирования; Правила не запрещают открытые компоненты, а требуют их перечислить и соблюсти лицензии. Укажите этот пункт в заявлении.

## 3. Соответствие документов комплекту заявителя

| Что запрашивается | Файл |
|---|---|
| Описание функциональных характеристик | `docs/01-funkcionalnye-harakteristiki.md` |
| Информация для установки и эксплуатации | `docs/02-ustanovka-i-ekspluataciya.md`, `docs/03-rukovodstvo-polzovatelya.md` |
| Описание процессов жизненного цикла, поддержки, персонала | `docs/04-zhiznennyj-cikl.md` (заполнить поля `<…>`) |
| Сведения о сторонних компонентах | раздел 2 этого документа |
| Экземпляр ПО для экспертной проверки | `dist/` + `deploy/install.sh`; демо-данные: `kafedra init -demo` |

Документы подаются в формате, который требует форма заявления (обычно PDF), и публикуются на сайте продукта. Сведения в заявлении, на сайте и в документах должны совпадать.

## 4. Что должен сделать правообладатель (в коде это решить нельзя)

1. **Оформить исключительное право.** Это главный риск проекта, см. раздел 5.
2. Убедиться, что заявитель соответствует требованиям к правообладателю (российская организация или гражданин РФ; для коммерческой организации — российский контроль более 50 %).
3. Соблюсти ограничение на выплаты иностранным лицам (менее 30 % выручки от продукта).
4. Создать сайт продукта: описание, документация, стоимость или порядок её определения, контакты поддержки; подтвердить право на домен.
5. Определить класс ПО по классификатору Минцифры (средства электронного обучения / управления обучением) — от класса зависят сроки требований о совместимости.
6. Заполнить поля `<…>` в `docs/04-zhiznennyj-cikl.md`, проверить название «Кафедра» на совпадение с чужими товарными знаками, заменить текст в файле `LICENSE`.
7. Провести и оформить испытания на двух российских ОС.
8. Подать заявление через Госуслуги с квалифицированной электронной подписью. Срок рассмотрения — до 45 рабочих дней; на запрос эксперта даётся 20 рабочих дней. После включения — ежегодное подтверждение сведений до 1 июня.
9. По желанию — зарегистрировать программу в Роспатенте (не обязательно, но упрощает подтверждение прав).
