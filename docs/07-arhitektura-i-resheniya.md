## 2. Ключевые решения

### Go и только стандартная библиотека
Один статический файл без зависимостей решает сразу три требования: быстрое развёртывание без контейнеров, отсутствие стороннего кода для реестра, минимальная поверхность атаки. В стандартной библиотеке Go 1.24 есть всё необходимое: HTTP-сервер с маршрутизацией, TLS, шаблоны с автоэкранированием, PBKDF2/HKDF/AES-GCM, ZIP и XML (для DOCX и резервных копий). Python отклонён: интерпретатор и десятки пакетов на сервере, сложнее поставка.

### Хранилище без SQL
Вывод исследования: **обойтись без СУБД можно**, и для одного сервера это лучше.

- Данные — типизированные коллекции в памяти; каждое изменение дописывается в журнал `journal.jsonl` (строка JSON + CRC32, `fsync`), периодически пишется снимок `snapshot.json` (атомарная замена файла).
- После сбоя питания журнал воспроизводится, оборванная запись отбрасывается (покрыто тестом).
- Каталог защищён блокировкой от второго процесса.
- Файлы материалов лежат на диске отдельно, в базе — только метаданные.

Плюсы: нечего устанавливать и администрировать, нет SQL-инъекций как класса, резервная копия — один файл, формат читается глазами.

Границы применимости: все записи находятся в оперативной памяти. Ориентир — до нескольких тысяч пользователей и сотен тысяч попыток/оценок на сервере с 2–4 ГБ ОЗУ (оценка расчётная; нагрузочные испытания на реальных объёмах не проводились). Выборки — линейный просмотр коллекций, индексов нет. Работа нескольких серверов с одной базой невозможна.

Если масштаб вырастет: слой `internal/store` изолирован, его можно заменить на СУБД из реестра российского ПО — **Postgres Pro** (или СУБД на базе PostgreSQL в составе Astra Linux / РЕД ОС). Это потребует драйвера PostgreSQL: стороннего либо собственной реализации протокола.

### Формат учебных материалов
Как устроено в коммерческих системах: встроенный редактор страниц + загрузка файлов «как есть» + пакеты SCORM из авторских средств. Принято:

1. **Основной формат — страница** с текстом в Markdown: читается на любом устройстве, правится за секунды, для ИТ-дисциплин удобны блоки кода и таблицы.
2. **Импорт DOCX** — потому что лекции преподавателей уже лежат в Word. Собственный конвертер переносит структуру в редактируемый текст; рисунки сохраняются как вложения.
3. **PDF, видео, изображения, аудио** показываются встроенным просмотрщиком браузера; **PPTX и прочее** — скачивание (надёжный показ PPTX в браузере без сторонних библиотек невозможен; рекомендуется сохранять слайды в PDF).
4. **HTML-файлы** принимаются, но показываются в изолированной рамке без сценариев.

Разбор PDF в текст не делается намеренно: результат ненадёжен, а браузер показывает PDF точно.

### Интерфейс
Серверная отрисовка страниц и минимум собственного JavaScript (таймер теста, автосохранение, панель редактора). Оформление — плоское, по образцу фирменной презентации заказчика: серо-синие шапка и подвал (#566a88), белые поля, светло-голубые плашки с тонкой рамкой, акцентные синий, зелёный и оранжевый; без градиентов и теней. Компоновка (шапка, боковое меню, карточки) сохранена от АСИМ. Шрифты — системные (внешние не подгружаются). Заголовок из двух строк и логотип задаются в конфигурации; нижняя строка с названием продукта и правообладателем зашита в код.

### Настройки
Все настройки — в одном `config.json` с отступами, включая раздел `settings`, который можно менять и из веб-интерфейса. Данные хранятся в `snapshot.json` с отступами; построчными остаются только журнал операций и журнал событий — это условие их защиты от сбоев и подмены.

### Excel, Word и PDF без сторонних библиотек
- **XLSX** и **DOCX** — это ZIP-архивы с XML; чтение и запись реализованы на `archive/zip` и `encoding/xml` (`internal/content/xlsx.go`, `docxwrite.go`). Старые двоичные форматы .xls и .doc не поддерживаются: бланки выдаются в .docx, который открывают Word, «МойОфис», «Р7-Офис», LibreOffice.
- **PDF** формируется собственным кодом (`internal/content/pdf.go`). Для кириллицы нужен внедрённый шрифт; включать шрифт в поставку — значит добавить сторонний компонент, поэтому берётся шрифт TrueType из операционной системы и разбирается здесь же. Цена решения: на сервере должен быть установлен шрифт с кириллицей.

### Чат («Общение»)
Реализован вариант с периодическим опросом: страница раз в 8 секунд запрашивает ленту сообщений. Постоянных соединений нет, поэтому чат одинаково работает напрямую и за общим веб-сервером без его перенастройки. Комнаты: чат курса (участники курса) и чат учебной группы (учащиеся группы и преподаватели её курсов). Модератор — преподаватель курса или группы и администратор. Ограничения: нет личных сообщений, уведомлений о новых сообщениях и поиска; показываются последние 300 сообщений.

### Почта
Отправка сертификатов — через `net/smtp` стандартной библиотеки на почтовый сервер организации. Приём почты (автоматическое открытие доступа по письму с анкетой) не реализован: потребовался бы доступ программы к почтовому ящику по IMAP, которого в стандартной библиотеке нет, и хранение пароля ящика.

## 3. Устройство

```
браузер ──HTTPS──► kafedra (один процесс)
                     ├─ защитная обвязка: заголовки, лимиты, сеанс, CSRF, роли
                     ├─ обработчики: курсы, тесты, задания, журнал, расписание, администрирование
                     ├─ internal/content: Markdown → HTML, DOCX → Markdown
                     ├─ internal/secure: пароли, ключи, TOTP, журнал событий
                     └─ internal/store: коллекции в памяти ⇄ journal.jsonl / snapshot.json
каталог данных: db/  files/  audit/  backup/  master.key
```

Правило для разработчиков: внутри функций, передаваемых в `Update`, `Find`, `Count`, `First`, нельзя обращаться к хранилищу — блокировка не реентерабельна.

## 4. Проверка

- `go vet`, автоматические тесты всех пакетов с детектором гонок (в комплект исходных текстов не включены).
- Сквозная проверка: вход, смена пароля, второй фактор, импорт DOCX, загрузка и отбраковка файлов, тест, задание, оценивание, журнал, рейтинг, расписание, блокировка, разграничение доступа, CSRF, журнал событий, резервная копия и восстановление, удаление персональных данных.
- Фаззинг разборщиков Markdown, DOCX, XLSX и шрифтов TrueType.
- Сформированные DOCX и XLSX открыты в LibreOffice; PDF-сертификат проверен средствами poppler (шрифт внедрён, текст извлекается) и просмотрен.
- Визуальная проверка основных страниц в Chrome (ПК и телефон), ошибок в консоли браузера нет.

Не проверялось: работа на российских ОС (сборка и тесты выполнялись в обычном Linux x86-64; исполняемый файл для ARM64 собран, но не запускался), нагрузка, независимый аудит безопасности, сценарий `install.sh` на реальном сервере, импорт сложных документов Word (формулы, сноски, вложенные таблицы переносятся упрощённо или теряются).

## 5. Ограничения версии 1.0 и план развития

| Нет в версии 1.0 | Комментарий |

| SCORM / xAPI | нужен для готовых курсов из авторских средств; реализуемо собственными силами |
| Видеоконференции | интеграция со сторонним сервисом по ссылке (поле «аудитория или ссылка») |
| Рассылка по электронной почте | отправляется только сертификат; остальные уведомления — внутри системы |
| Единый вход (ЕСИА, LDAP/AD), интеграция с 1С:Университет | типовой запрос вузов |
| Вопросы на соответствие, упорядочение, проверка кода | расширение банка вопросов |
| ИИ-функции, адаптивные траектории, геймификация, сертификаты | тенденции рынка; осознанно отложены |
| Учебные планы, рабочие программы дисциплин, ведомости, зачётные книжки | документы ЭИОС по ФГОС; сейчас их можно публиковать как материалы курса |
| Автоматическое открытие доступа по получении письма с анкетой | не реализовано: доступ после проверки анкеты открывает администратор |
| Личные сообщения, уведомления о новых сообщениях чата | нет |
| Проверка подлинности сертификата по номеру, подпись и печать на сертификате | сейчас номер и дата; выдача — без утверждения преподавателем |
| QR-код для подключения второго фактора | ключ вводится вручную; интернет для второго фактора не нужен |
| Античит и прокторинг | фиксируется только адрес попытки |
| Английский интерфейс | только русский |
| Мобильное приложение | адаптивный веб-интерфейс |
